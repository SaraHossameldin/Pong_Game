# Pong Game — FPGA VGA Implementation

A hardware implementation of a Pong-style game written in **Verilog**, designed to run on an FPGA and output video over a **VGA interface** at **640×480 @ 60 Hz**. The project was developed using **Xilinx Vivado** and targets a standard Xilinx FPGA board with a VGA connector.

## Overview

This project implements the core hardware building blocks needed to drive a VGA display from an FPGA:

- A **clock divider** that scales the FPGA's system clock down to the 25 MHz pixel clock required by the 640×480 VGA standard
- A **VGA sync generator** that produces the horizontal and vertical sync signals and tracks the current pixel position (row and column) in real time
- A **frame buffer** that holds a 640×480 pixel array in FPGA block RAM, with a per-pixel read interface
- A **VGA test module** that combines the above to render a checkerboard-and-gradient test pattern to the screen
- A **Pong paddle module** stub (`PaddleMovement.v`) scaffolded for future game logic

---

## Hardware Requirements

- A Xilinx FPGA development board with a VGA output connector (e.g. Basys 3, Nexys A7, or similar)
- A VGA monitor
- A VGA cable
- A USB cable for FPGA programming

## Module Descriptions

### `VGAtest.v` — Top-level

The top-level module that connects all submodules and drives the physical VGA pins.

**Ports:**

| Port | Direction | Width | Description |
|---|---|---|---|
| `vgaRed` | output | 4 bits | Red channel (4-bit DAC) |
| `vgaGreen` | output | 4 bits | Green channel (4-bit DAC) |
| `vgaBlue` | output | 4 bits | Blue channel (4-bit DAC) |
| `Hsync` | output | 1 bit | Horizontal sync signal |
| `Vsync` | output | 1 bit | Vertical sync signal |
| `clk` | input | 1 bit | System clock (FPGA board clock) |
| `rst` | input | 1 bit | Synchronous reset |

The module renders a test pattern: a 32×32 pixel checkerboard XOR'd with a colour gradient (red varies with column, green varies with row, blue is off).

---

### `SyncGenerator.v` — VGA Sync Generator

Generates the horizontal and vertical sync pulses and exposes the current scan position.

**Module:** `sync_generator`

**Ports:**

| Port | Direction | Width | Description |
|---|---|---|---|
| `clk` | input | 1 bit | 25 MHz pixel clock |
| `rst` | input | 1 bit | Synchronous reset |
| `Horizontal_sync` | output | 1 bit | HSYNC signal to VGA connector |
| `Vertical_sync` | output | 1 bit | VSYNC signal to VGA connector |
| `currentRow` | output | 10 bits | Current scan line (0–524) |
| `currentColumn` | output | 10 bits | Current pixel column (0–799) |

The sync generator counts through the full 800×525 frame (including blanking and sync intervals) and computes sync polarity combinatorially each cycle.

---

### `PixelClock.v` — Clock Divider

Divides the system clock by a parameterized factor to produce the pixel clock.

**Module:** `clockDivider #(parameter n = 4)`

| Parameter | Default | Description |
|---|---|---|
| `n` | 4 | Division factor. Set to match your board's clock to get 25 MHz. For a 100 MHz board clock, use `n = 4`. |

Internally uses `counter_x_bit`, a parameterized modulo counter also defined in this file.

---

### `FrameBuffer.v` — Frame Buffer

A 640×480 single-bit frame buffer backed by FPGA block RAM. Each pixel is stored as a single bit (on/off). The current pixel value is read out combinatorially based on the current scan position.

**Module:** `FrameBuffer`

**Ports:**

| Port | Direction | Width | Description |
|---|---|---|---|
| `currentRow` | input | 10 bits | Current scan row from sync generator |
| `currentColumn` | input | 10 bits | Current scan column from sync generator |
| `currentPixel` | output | 1 bit | Pixel value at current position |

Initialized to all zeros (black screen) at startup. Write logic for game objects (ball, paddles) would be added here.

---

### `PaddleMovement.v` — Paddle Module (stub)

A scaffolded module named `Pong` with no ports yet defined. This is where paddle movement, ball logic, and collision detection would be implemented to extend the project into a playable game.

---

### `counter_x_bit.v` — Parameterized Counter

A reusable modulo counter used by the clock divider.

**Module:** `counter_x_bit #(parameter x = 3, n = 6)`

| Parameter | Description |
|---|---|
| `x` | Bit width of the counter register |
| `n` | Modulo value (counter resets to 0 after reaching n−1) |

---

## VGA Timing Reference

The sync generator is hardcoded for the **640×480 @ 60 Hz** standard:

| Parameter | Value |
|---|---|
| Pixel clock | 25.175 MHz (≈ 25 MHz) |
| Horizontal total | 800 pixels |
| Horizontal active | 640 pixels |
| Horizontal sync pulse | columns 0–95 |
| Vertical total | 525 lines |
| Vertical active | 480 lines |
| Vertical sync pulse | rows 0–1 |

## How to Open and Run in Vivado

### Opening the project

1. Launch **Xilinx Vivado**.
2. Click **Open Project** and select `Pong.xpr`.
3. Vivado will load all source files automatically.

### Running synthesis and implementation

Either use the Vivado GUI (click **Run Synthesis** → **Run Implementation** → **Generate Bitstream**), or run the included Tcl script in batch mode:

```bash
vivado -mode batch -source VGAtest.tcl
```

On Windows you can also use the included batch wrapper:

```bat
runme.bat
```

### Programming the FPGA

1. Connect your FPGA board via USB.
2. In Vivado, go to **Open Hardware Manager → Open Target → Auto Connect**.
3. Click **Program Device** and select the generated `.bit` file.
4. Connect a VGA monitor to the board's VGA port.

> **Clock configuration:** The `clockDivider` module divides the system clock by `n`. If your board runs at 100 MHz, the default `n = 4` gives 25 MHz — correct for 640×480. If your board runs at a different frequency, update `n` in `VGAtest.v` accordingly.
